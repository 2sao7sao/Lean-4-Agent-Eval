# 验证范围与信任边界

## 当前形式模型

[Verdict.lean](../formal/Lean4AgentEval/Verdict.lean) 定义四种判定、失败优先合并、非空必检聚合，以及按合同 ID 查询回执的函数。命名定理共 11 个，包含辅助性质。

- 总结论通过，当且仅当必检列表非空且每项通过。
- 已知失败在与错误、未知并存时仍使总结论失败。
- 任意必检项非通过会阻止总结论通过。
- 缺失必检项按未知处理，不能靠省略回执获得通过。

`python3 scripts/check_formal.py` 构建固定工具链的模型，审计全部命名定理，并运行四个负向控制。仅允许标准公理 `propext / Classical.choice / Quot.sound`；`sorryAx` 和额外公理不能成为已验证结果。控制中的不安全声明仅临时生成于忽略提交的构建目录。

回执在 `.artifacts/formal-verification.json`，包含工具链、命令、源码哈希和控制结果。这是本地构建与公理审计，不声称完成独立内核复核或对恶意源码的隔离构建。

## 未被证明的内容

| 边界 | 额外工作 |
|---|---|
| 用户意图 → 合同 | 正反例校准、假设审查、确认记录 |
| 验收条件 → 检查器 | 测试、攻击性反例、裁判误差评估 |
| 真实执行 → trace | 独立采集、权限边界、完整性与来源验证 |
| CSV/PPT → 检查输入 | 严格解析、实际文件和渲染验收 |
| Python → Lean 模型 | 可靠绑定或实现等价性；当前未建立 |
| 测试集 → 业务总体 | 代表性抽样、隔离保留集和适当的统计推断 |

Lean 判定证明不能升级为“整个 Agent 已被形式验证”。数值检查不能代替 PPT 可读性、数据真实性或结论质量验收。

## M1 的新增范围

确定性规则解析器、合同生成器和确认流程由 Python 回归测试验证，不在 Lean 证明范围内。它们支持列出的月度销售快照到 PPT 模板，不保证任意表述的需求完整性；用户需对照原始需求审查来源、提议规则和遗漏项。

需求确认依赖本地记录的确认人元数据，不认证身份。审查哈希用于检测内容变化，不防止主动篡改者重算哈希。正式执行仍需受保护的身份、日志与完整合同绑定。合成 demo 中的确认不构成真实业务批准。

## 实验与质量判断

按业务任务分层，分别记录任务数量与每题重复次数。固定 Agent、模型、提示、工具、数据、合同和评分器版本，说明抽样、相关性和区间方法。同题重复不能代替任务覆盖。

`pass@k` 衡量多次尝试至少一次成功，须说明重试成本及正确候选如何选择。日常可靠性另外报告单次成功和多次一致成功。未知率、基础设施错误率、违规率单列，不从分母静默移除。

模型裁判需要冻结量表、人工校准集与分歧复核；重点检查误放行、误拒绝、风格偏好、提示注入及关键词投机。形式证明、确定性检查和经验评分分别标注，不能合成一个“形式置信百分比”。
