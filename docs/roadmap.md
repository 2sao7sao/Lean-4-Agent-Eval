# 实施路线与完成标准

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| M0 产品骨架（已建立） | README、架构、Schema、模块接口、业务样例、Lean 判定核心 | 合同引用有效、参考数值可重算、负向控制有效、形式模型检查有效 |
| M1 需求到合同（销售规则流程已实现） | 多轮沟通、澄清、动态验收标准、来源与需求确认 | 合成样例跑通；边界回归有效；继续补充真实需求与用户审查样本。生产执行冻结另需身份/注册表与后续验收器 |
| M2 自动评估集 | 变体、参考计算、覆盖矩阵、评分器反例 | 场景可执行；答案可核验；错误产物被拒绝；开发/校准/保留集隔离 |
| M3 真实业务闭环 | Agent 适配器、采集、CSV/分析/PPT 验收 | 真实执行关联输入、trace、分析、PPT 和渲染；正确/错误/缺证据/故障可复现 |
| M4 可信迭代 | 裁判校准、预算化实验、候选改进与回归 | 报告任务覆盖和稳定性；保留集不泄漏；标准版本化；不能靠放宽标准晋级 |
| M5 扩展 | 编程、文案和更多办公场景 | 通过适配器和领域检查器复用核心 |

M3 前不报告真实 Agent 成功率或 PPT 质量，M4 前不报告总体可靠性。建立形式模型到运行时的可靠绑定前，形式保证仅限明确列出的 Lean 性质。

M1 当前采用本地领域规则，不依赖模型。LLM 辅助提取可作为后续适配器，但必须保留来源、澄清、不确定状态和独立合同检查；不能以接入模型替代需求语义验证。
