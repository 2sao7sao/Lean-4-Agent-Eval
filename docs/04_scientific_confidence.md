# 科学置信：证明、测量与泛化分别负责什么

本文是实验设计建议，尚无真实 agent 数据。示例阈值不能直接用作上线标准。

## 不使用一个模糊的“可信分”

至少分别报告四类证据：

| 问题 | 支持证据 |
|---|---|
| 规则表达了用户真正想要的吗？ | 需求来源、正反例、业务复核、遗漏分析 |
| 检查器实现了这条规则吗？ | 形式化性质、测试、变异测试、独立实现对照 |
| 此次运行通过了吗？ | trace、环境状态、最终产物、逐项判决 |
| 对目标任务群体有多可靠？ | 代表性样本、重复试验、区间与分层报告 |

逻辑上的证明不自带“95% 置信”；统计置信区间也不是定理证明，更不是某个具体输出为真的概率。

## 一个数字例子

在独立同分布 Bernoulli 试验、固定样本量、判定无误且零失败的条件下，失败率 p 的单侧 95% 精确上界可由 `(1-p)^n = 0.05` 得到：

`upper = 1 - 0.05 ** (1 / n)`

- 20 次零失败：上界约 13.91%。
- 100 次零失败：上界约 2.95%。
- 300 次零失败：上界约 0.99%。

这是从二项模型推导出的示例，不是在说重复测同一道题 300 次，就证明所有办公任务的失败率低于 1%。相关性、分布变化或评分误差都会改变解释。二项区间的基础见 [NIST 精确区间](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbici.htm)。

频率学置信度描述方法在重复抽样中的覆盖表现；不能简单解释为“真实参数落在本次区间内的概率是 95%”。

## 运行前固定实验问题

1. **目标总体**：什么用户、任务类型、难度、数据源和文件规模；对哪些任务不作结论。
2. **主指标**：建议以端到端任务成功为核心；trace 指标用于硬约束与诊断。
3. **比较对象**：基线和候选的模型、提示词、工具、依赖、数据与配置版本。
4. **样本计划**：分层、任务数量、每题重复数、是否配对、最小有意义差异、预算与停止规则。
5. **统计方法**：固定样本量分析，或提前设计有效的序贯方法；不能边看边测直到结果显著。
6. **验收规则**：效应门槛、区间方向、关键失败约束和未解决证据的处理。

先用试点估算成功率、方差、相关性和运行成本，再确定正式样本量。不能凭空给所有业务统一设置“50 条就够”或“90 分上线”。

## 样本划分与指标

开发集用于调试；评分器校准集用于对齐人工标准；冻结验收集用于受控比较；上线后另做漂移监测。来自同一文档、同一客户或同一模板的变体按组划分，防止近重复泄漏。

若 100 个任务各运行 5 次，应分别报告“100 个任务、500 次运行”。同一任务内结果有相关性，不能无条件把 500 次当作 500 个独立同分布样本。可按任务聚类重采样，或使用适当的层级模型；具体方法需要按数据结构选择和验证。

建议同时报告：

- 每类任务的端到端成功率、样本量和适用区间。
- 已确认的硬性违规，以及 `UNKNOWN/ERROR` 的比例与原因。
- 单次成功、重复稳定性、重试后的成功；明确哪个才是产品承诺。
- 成本、延迟、人工介入率、超时和运行失败。
- 必检需求的覆盖率与证据缺失率；不能用它们替代成功率。

`pass@k` 表达多次尝试至少一次成功；`pass^k` 表达 k 次都成功。二者回答不同问题。只有独立且成功率相同的简化模型下，才直接写成 `1-(1-p)^k` 与 `p^k`；实际应保留任务分层，不能把全体平均成功率简单取 k 次方。[τ-bench 作者论文](https://arxiv.org/abs/2406.12045)

普通独立比例可考虑 Wilson 区间，罕见失败可考虑精确区间；这不是所有 agent 数据的通用区间配方。[NIST 比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

不要悄悄移除基础设施错误。保留全部计划运行的分母；另报告有效运行数、故障类别，以及预先约定的条件成功率。业务运行失败与评估器失败分开，重新运行也保留原记录。

## 模型评分器也要被评估

模型打分会存在位置、冗长、自我偏好等偏差。某篇论文的总体一致率不能证明它在我们的办公任务上可靠。[LLM-as-a-Judge 作者论文](https://arxiv.org/abs/2306.05685)

建议流程：

1. 写带正反例和边界例的 rubric，先定义“支持充分”“结论越界”等词的含义。
2. 由人独立标注一批样本，处理分歧，保留不确定标签。
3. 对评分器测量误放行、误拒绝、分任务偏差和重复稳定性，必要时做盲评和顺序互换。
4. 要求评分给出可定位的证据；没有依据时允许弃权。评分器的自报置信不能当成已校准概率。
5. 上线后抽审，变更模型／提示词／数据分布后重新校准。

多个 judge 的一致不是独立性的证明，也不是事实正确性的证明。若生成者、出题者与评分者共享同一种偏差，自动循环可能稳定地奖励错误。给评分器看的 agent 输出和检索材料要作为数据处理，防止其中的指令改变评分规则。

## 改进是否成立

在同一批任务上比较基线和候选，保存配对结果与失败类别。尝试多个候选、多指标或反复查看验收集时，要控制选择偏差；探索集的最好成绩不直接称为泛化提升。

自动迭代采用显式预算、候选数与停止条件。冻结集不作为日常修复反馈；看过其错误后产生的新规则／训练样本，应进入后续版本并安排新的验收安排。

对于“为什么失败”的分析，trace 只能给出线索。通过改变单个因素、重放、替换中间结果或对照运行才能加强因果判断；纯相关诊断标为假设。外部服务随机性和环境漂移应记录，不能假装回放能够完全复现真实世界。

## 建议报告句式

“在合同 C、数据版本 D、agent 配置 A 和任务总体范围 P 下，我们执行了 N 个任务、R 次运行。确认通过 X、失败 Y、证据不足 U、评估错误 E。形式化保证仅覆盖规则集合 F；经验成功率及区间按方法 M 计算。尚未覆盖的需求和人类判断为 H。”

这比“Lean 已保证 agent 科学可信”更准确，也更便于决定下一步补什么证据。
